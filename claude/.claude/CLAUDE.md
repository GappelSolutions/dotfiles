# Code Comments

Never add comments to application/product code (`.ts`, `.html`, `.css`/`.scss`, `.json`, `.csproj`, `.cs`, `.xml`, config files inside app projects, etc.) — e.g. anything under `../../nova/ModularMonolithGDM` or similar product repos. Write self-explanatory code instead; if logic is truly non-obvious, prefer a better name/structure over a comment.

Comments are fine in infra/dotfiles context: this repo, Nix, shell scripts, CI/CD, Dockerfiles, and similar tooling/config-as-code.

# Token Discipline

- Don't re-dump unchanged output. Grep for `error`/`Error(s)` instead of re-printing full build/warning logs.
- Scope recursive commands (`find`, `grep -r`) and exclude `bin/`, `obj/`, `node_modules/`, `.git/` up front.
- Tail/grep logs for the relevant window, not full scrollback.
- Batch related read-only checks into one Bash call instead of one call per check.
- Stuck after 3-4 diagnostic attempts on the same issue? State the hypothesis and test it directly, or ask — don't keep escalating tool breadth.
- Prefer `getComputedStyle`/DOM reads over screenshots; when a screenshot is needed, scope to viewport and view via Read, not inline.
- If several tool calls pass without progress, say so instead of silently continuing.

## agenix

It is NOT `~/.ssh/id_ed25519` and NOT the machine's `/etc/age/host.key` — agenix's default identity search misses it and fails with "no identity matched any of the recipients", so always pass it explicitly:

```sh

```

# Playwright

Only use when the user asks for a browser check, or nothing else can verify the behavior — not as a default "let's confirm it works" step. Never run `playwright install` (browsers are provided system-wide, download is disabled on purpose).

- Devs project already has `playwright`/`@playwright/test`: use its own install/config.
- Ad hoc/no project: use `nix/scripts/browser-scratch/` (git-tracked, pinned to the installed browser revision).
- Prefer `innerText()`/`getComputedStyle` reads over screenshots; script one bounded flow and stop; always `browser.close()`.

# Git Conventions

Branch: `TYPE/TICKET_ID-short-description` (`feat`, `bug`, `hotfix`, `chore`).
Commit/PR title: `#TICKET_ID TYPE(component): description` — omit `#TICKET_ID` entirely if there's no ticket, never `#0`.
English only, for branches/commits/PRs. No "Generated with Claude Code" in PR descriptions. Always `az repos pr work-item add --id PR_ID --work-items TICKET_ID`.

Lazygit: `o` open in Azure DevOps, `P` push, `p` pull, `c` commit.

# Jujutsu (jj)

If `.jj/` exists, prefer jj over git: `jj describe -m` (commit), `jj new -m` (branch/checkout), `jj bookmark create` (branch), `jj git push --bookmark`, `jj git fetch && jj rebase -d main@origin` (pull), `jj undo` (undo anything).
