# Angular (company standard)

This is the same skill structure checked into every company Angular project — the
architecture (Nx vertical-slice libs, Bun-only tooling, Spartan/Tailwind v4,
generator wrappers, zoneless signal state) is the shared stack, not something
specific to this app. Examples below use placeholder names (`apps/my-app`,
`libs/my-app/home`, ...) — substitute this project's own app/domain names, the
pattern is identical everywhere this skill is installed.

## Non-negotiables (read before touching anything)

- **Bun only.** Never `npm install`/`pnpm install`/`npx`. Exact-pinned deps
  (`bunfig.toml`'s `exact = true`) — a version bump edits the pin, doesn't add a range.
- **Never call `ng`/`nx generate` raw for scaffolding a domain, component, or
  service.** This repo's `bun g:*` wrappers bake in directory layout, tags, prefix,
  and i18n scaffolding that the bare generator doesn't know about. See
  [nx-generators.md](references/nx-generators.md).
- **Zoneless.** No `NgZone`, no `fixture.detectChanges()` for anything driven by a
  signal update after the initial render — see [testing.md](references/testing.md).
- A plain non-interactive shell (agent Bash tool included) doesn't load direnv —
  Playwright/devenv-provided env vars need `devenv shell -- <command>` in front.

## Architecture map

```
apps/my-app        thin app shell (bootstrap only) — apps/my-app-e2e is its Playwright suite
libs/myorg/*       @myorg/kit-*  — cross-project shared foundation, prefix org/hlm
libs/my-app/*       @my-app/*     — app-specific domains, one lib per domain, prefix app
```

`libs/myorg/kit-ui` is not one project — it's a directory of independent
per-primitive projects (button, input, field, ...), each generated by
`@spartan-ng/cli:ui`. A domain (either namespace) is never split into
`feature`/`data-access`/`ui`/`util` sub-libs unless it's genuinely big enough to need
independent build/test/lint units.
