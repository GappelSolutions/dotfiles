# Spartan/Helm + Tailwind v4

## Tailwind v4 is CSS-first — no `tailwind.config.js`

- PostCSS must be wired via a **literal** `.postcssrc.json` — Angular's builder only
  recognizes `.postcssrc.json`/`postcss.config.json`, not `.mjs`/`.js`/`.cjs`. Get the
  filename wrong and Tailwind utilities pass through unprocessed with **no error** —
  if styling silently does nothing, check this file first.
- Global styles import Tailwind with `@import 'tailwindcss';`, not the old
  `@tailwind base/components/utilities;` directives.
- Theme customization is `@theme` blocks in CSS, not a JS config object.

## `kit-ui` primitives

- Each primitive (`button`, `input`, `field`, `label`, `separator`, `skeleton`,
  `sonner`, `utils`, ...) is its own Nx project under `libs/ensor/kit-ui/<primitive>`,
  generated by `@spartan-ng/cli:ui` via `bun g:kit-ui <primitive>` — never hand-roll
  one, and never nest a manually-created library inside `kit-ui` (`ng-packagr` treats
  any nested `ng-package.json` as a secondary entry point and breaks).
- These keep Spartan's own `hlm` selector prefix rather than fighting the CLI's
  generator default — don't rename to `esr`/`gdm`.
- `bun docs` (Storybook, `libs/ensor/kit-ui/storybook`) is the fastest way to see
  existing usage conventions before adding a new primitive; stories are tagged
  `autodocs`, and `src/stories/foundations/*` documents theme tokens/layout patterns
  rather than a single component.

## Theming

- `kit-theme`'s `ThemeService` is a generic mechanism only — a `theme` signal plus
  `setTheme(name)`, toggling a `theme-<name>` class on `<body>` (matches the class
  scoping `@spartan-ng/cli:ui-theme --prefix` generates). It carries no
  tenant-specific data itself.
- `theme.css` ships the `ensor` company-default palette as plain unscoped
  `:root`/`:root.dark` rules, plus `DEFAULT_TENANT_THEME = 'ensor'`, so a new
  consuming app gets sane default branding for one `@import` + `setTheme(DEFAULT_TENANT_THEME)`.
- `apps/gdm-ui/src/styles.css` imports that, then owns any `.theme-<tenant>`
  overrides itself. A resolved-at-runtime tenant just calls `setTheme(<name>)` — the
  lib doesn't care which name it gets.

## Responsive — tablet-first, not mobile-first

Tailwind's own default assumes mobile-first (unprefixed utilities = smallest
viewport, `md:`/`lg:` scale up). This project inverts that: **unprefixed
utilities target the tablet viewport** as the design baseline, since that's the
primary device class for this app's users.

- Scale up to desktop with `md:`/`lg:` as usual.
- Scale down to phone with `max-md:` (or an explicit `max-w-*` variant), not by
  assuming the unprefixed rule already covers phone.

## Selector prefixes (recap)

`esr` = `@ensor/kit-*` shared components (except `kit-ui` primitives, which keep
`hlm`) · `gdm` = anything GdmUi-app-specific.
